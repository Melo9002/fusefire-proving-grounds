# Phase 3 Task 3.1 — Sealed Building Assembly Certification

## Result

`city_industrial_shell_i`, backed by `city_kit_industrial/building-i`, is the first certified reusable building assembly. It is a complete monolithic exterior shell with a street-facing pedestrian door and garage/service door. It remains exterior-only and tactically solid.

The certification passed its objective validation and rendered inspection in all four supported orientations.

## Existing representation audit

Before this task, relevant facts were split across four existing representations:

| Existing owner | Useful authority | Gap before certification |
|---|---|---|
| `SemanticAssetCatalog` | Confirmed complete-building identity, model-local `-Z` working face, contexts and procedural approval | Descriptive meaning did not pin a placement or dependency revision |
| `AssetCatalog` and `native_bounds.json` | Scale 10, source anchor/orientation and native geometry bounds | A later calibration change could silently drift from duplicated placement values |
| `IndustrialBuildingPlacementProfiles` | Per-shell bounds, grid footprint and frontage normalization | The profile was reusable but not independently certified; most values are rounded |
| `EnvironmentBuildingDefinition` / module | Prebuilt-shell status, tactical footprint, visual envelope, clearance apron and visible asset reference | No dependency hashes, named frontage relationship, required/optional component record or certification state |

The new contract extends `EnvironmentBuildingDefinition`; it does not add another asset catalog. Existing closed derived buildings, open shelters and the other 19 prebuilt shells retain their established behavior.

## Minimal assembly contract

`EnvironmentAssemblyContract` records:

- stable assembly ID;
- assembly role and completeness;
- required or optional imported components and local transforms;
- per-component GLB SHA-256 and resolved calibration fingerprint;
- explicit tactical footprint;
- approved visual envelope;
- required clearance cells;
- named relationships, currently `street_frontage`;
- supported rotations;
- certification state and the latest validation failures.

It validates against the existing building/module, semantic catalog and asset calibration path. It distinguishes sealed buildings, open shelters, modular structures and equipment parcels without implementing those later assembly types.

The current calibration fingerprint covers the calibration schema version, uniform scale, corrective yaw, anchor mode, anchor offset and native bounds for the relevant asset. The component transform, spatial reservation and tactical footprint are pinned literals. They are not regenerated from the current module during validation, so changes invalidate the record instead of moving its acceptance target.

## Automated validation

The focused suite validates the live contract, real presentation geometry and these negative cases:

| Invalid configuration | Required failure |
|---|---|
| Missing imported component | `MISSING_REQUIRED_ASSET` |
| Frontage contrary to normalized physical face | `FRONTAGE_MISMATCH` |
| Truncated frontage clearance | `INVALID_CLEARANCE` |
| Asset reclassified as a fragment | `UNSUPPORTED_COMPLETENESS` |
| Changed GLB dependency | `STALE_GEOMETRY_DEPENDENCY` |
| Changed calibration dependency | `STALE_CALIBRATION_DEPENDENCY` |
| Rotation outside 0–3/module support | `UNSUPPORTED_ROTATION` |

For rotations 0–3, the test instantiates the actual imported asset through `ModularEnvironmentPresenter`, applies an independent expected-frontage table, and checks its resolved mesh bounds against the rotated approved envelope. The intentional 0.01 envelope seam shrink is covered by a 0.021 containment tolerance; it does not hide cell-scale errors.

All automated commands passed: six focused suites reported zero failures, asset calibration reported 3,461 checks / zero failures, and semantic coverage reported 2,323 checks / zero failures across all 315 confirmed assets. Godot emitted host-environment warnings about the Windows certificate store and unwritable user log path during sandboxed headless runs; neither affected execution or assertions.

The broader generation subsystem initially exposed one obsolete assumption in `semantic_district_generation_test.gd`: blindly applying `ceil()` to the exact imported depth turned 13.000000715 units into 14 tactical cells. The updated contract now checks the explicit reviewed footprint, requires it to contain measured geometry within a 0.001 import tolerance, and still forbids wasting a full extra cell on either axis. The corrected semantic district suite passed with zero failures. A final generation run, including project parsing and automatic discovery of the new certification suite, reported **22 passed, 0 failed and 9 explicit-only visual/stress checks skipped** in 255.55 seconds.

## Tactical boundary and discrepancy

The assembly contract records tactical cells but never derives them from the GLB. `EnvironmentModuleMapWriter` and `MapData` remain authoritative. Every 11×13 footprint cell is explicitly non-walkable, full cover and LOS blocking. The visible exterior doors therefore do not imply traversal.

The tactical footprint is intentionally conservative: it rounds the 10.281-unit width outward to 11 cells and treats the 13.000000715-unit depth as 13 cells after recognizing import noise. The visual envelope retains the measured continuous dimensions.
