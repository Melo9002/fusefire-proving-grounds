# Phase 1, Task 1.3 — Visual-Envelope Rotation and Reservation

## Result

The current production implementation already satisfies the required visual-envelope contract. The correction was present in revision `cce128b`; Task 1.3 did not rewrite production code. This task documented the contract, established broader permanent regression coverage, and demonstrated that the tests fail against the pre-fix revision `044fc24` for both incorrect bounds and incorrect placement decisions.

## Root cause and current implementation

The old implementation advanced the AABB through repeated quarter turns while continuing to translate with `definition.size.y - 1`. That stale depth is only valid for the first turn. Once a rectangular module exchanges axes, rotations 2 and 3 accumulate a translation error even though the final envelope extents may still look correct.

`EnvironmentModuleLayout.world_visual_envelope()` now treats the authored envelope as a continuous module-local AABB. It transforms all eight corners through the canonical `EnvironmentModuleDefinition.rotate_point()` contract, preserves Y, adds the placement origin and elevation, and encloses the resulting world points. It then applies the established `0.01` inward seam tolerance when every dimension can support it.

The authored meaning is unchanged:

- X/Z are continuous coordinates in the same module-local frame as visual anchors; they may be offset or extend beyond tactical cell centers.
- Y is continuous height relative to the placement elevation.
- Bounds are geometrically enclosed before the seam epsilon is applied.
- Same-layer positive-volume intersections are rejected by `EnvironmentModuleLayout.try_add()`.
- Visual reservations remain independent of footprint cells, clearance cells, traversal, cover, and line of sight.

## Permanent regression coverage

`tests/coherent_visual_envelope_test.gd` independently transforms AABB corners without invoking the production point-transform helper. It covers:

- a square 4×4 control;
- an offset 2×5 envelope;
- a differently offset 4×3 envelope;
- rotations 0, 1, 2, and 3;
- vertical offsets and extents;
- a collision at the corrected rotation-2 location;
- a legitimate placement in the region incorrectly reserved by the old transform;
- boundary-touching envelopes accepted by the intentional epsilon;
- a visual-only module with an empty tactical footprint.

The generation subsystem filename pattern discovers the new suite automatically as `coherent_visual_envelope_test`.

| 4×3, rotation 2 | position `(8.860001, 2.61, 20.21)` | `(7.86, 2.61, 20.21)` | X reservation displaced by -1 |

## Remaining limits

- Reservations are axis-aligned world AABBs, so rotated non-box geometry may reserve conservative empty corners. This task corrects placement, not shape precision.
- Visual collisions are compared within the same authored placement layer. Deliberate cross-layer overlap remains possible by design.
- The contract covers supported horizontal quarter turns and unit-grid placement, not arbitrary rotation or scale.
- Correct bounds depend on correctly authored visual envelopes; they do not validate the source calibration itself.
